#### **USER Story:**

**As a** chartering user working an email in Smart Inbox,
**I want to** see an Inquiry the AI already drafted from that email's content when there's enough detail, or create one manually when there isn't — and be able to add further manual Inquiries alongside it,
**So that** I can turn correspondence into a commercial Inquiry record with as little re-keying as possible, whatever the source email actually contains.

---

#### **acceptance criteria:**

1. **Entry point:** the "Inquiry" icon on the reading pane's side rail opens the Inquiry panel for whichever email is currently open, as a tabbed form.

2. **Starting state — AI-created:** if the email has enough content for AI extraction, the panel opens with a single **AI-created** tab (marked with a sparkles icon in the tab bar and an emerald **"AI-created"** badge above the form), already treated as created — its fields are pre-filled from the extraction as an editable starting point, not read-only.

3. **Starting state — not enough data:** if the email doesn't have enough content, the panel opens with a single, blank, **not-yet-created** manual tab instead, alongside an amber badge reading **"Not Enough data to Create Inquiry, Create Manually."**

4. **Tab bar:** every Inquiry attempt on this email — the AI one (if any) plus every manual one — is its own tab. The AI tab, when present, can never be removed (no remove control is shown on it, unlike manual tabs). A not-yet-created tab is labelled "New Inquiry"; once created, its label switches to the generated Cargo Number with a checkmark icon.

5. **Adding a manual tab ("+"):** clicking "+" adds a new manual tab and switches to it immediately.
   - If the email has AI-extracted data available (whether or not the AI tab itself has been "created" yet), the new tab is pre-populated with a deep, independent copy of that same underlying data as an editable starting point — every nested list (ports, commissions, cargo income/expense, offices, persons in charge) is cloned, not shared by reference. The Cargo Number is left blank, since it's only assigned at creation time (AC 8).
   - If the email has no extractable data at all, the new tab starts completely blank, same as AC 3.

6. **Removing a tab:** hovering a manual tab reveals an "✕" to remove it (the AI tab has no such control — see AC 4). Removing the last remaining tab closes the whole Inquiry panel rather than leaving an empty tab bar.

7. **Per-tab isolation:** each tab — AI or manual — holds its own independent copy of the Inquiry data. Editing one tab's fields never affects any other tab's data, even a manual tab that was originally seeded from the same AI extraction via "+" (AC 5).

8. **Creating a manual Inquiry:** a not-yet-created tab shows **Cancel** / **"Create Inquiry"** actions at the bottom of the form. Cancel removes just that tab (same effect as its tab-bar "✕"). "Create Inquiry" generates a Cargo Number in the format `CR-[YYYY]-[NNN]` (deterministic per email + tab, so it's stable across re-renders) if the tab doesn't already have one, marks the tab as created, and the header switches from "New Inquiry" to a clickable Cargo Number link.

9. **Opening a created Inquiry:** clicking the Cargo Number link — on the AI tab or any created manual tab — opens the real Inquiry Detail overlay for that record.

10. **Convert to Fixture:** once a tab is created, a **"Convert to Fixture"** button appears next to its Cargo Number. Clicking it hands that tab's current field data to create a linked Fixture and the button becomes a disabled, checked **"Converted to Fixture"** state. This is available independently on every created tab on the email — an AI tab and any number of manual tabs can each be converted to their own separate Fixture.

---

#### **Out of scope**

* The Inquiry field-level form itself (Cargo Name/Category, Ports of Loading/Discharge, Commissions, etc.) — it's the same field set as the standalone Inquiry module and isn't re-specified by this story.
* The Fixture creation form and Fixture-side behaviour once "Convert to Fixture" is clicked — covered by its own story ("Fixture – Auto List & Manual Creation").
* Real AI/LLM extraction — "AI-created" content is pre-authored per demo email, not generated by a live model at runtime.
* Persisting manual tab drafts across a side-panel remount (e.g. navigating to a different email and back) — see Open Items.

#### **Open items**

1. **Manual tab drafts are not persisted** — all tab state (AI and manual alike) for this panel is local to the panel component and is lost if the side panel remounts, e.g. by switching to a different email and back. Only the fact that an AI Inquiry or a converted/created Fixture exists is remembered at the top level; in-progress manual tabs are not. This is a known, previously-accepted mockup limitation, but it directly affects "manual creation" and is worth re-flagging here.
2. **Cargo Number uniqueness isn't guaranteed across the app** — it's a deterministic hash of the email subject plus the tab's internal id, so a collision with a Cargo Number generated elsewhere (e.g. in the standalone Inquiry module) is theoretically possible, though not observed across the current 18-row demo set.
