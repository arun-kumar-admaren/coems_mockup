#### **USER Story:**

**As a user working with tables in the Engineering module,**
**I want** the ability to resize columns using a drag-and-expand icon — in the Group Worklog table, the Engineering listing page and the Engineering Task listing page
**So that** I can widen a column to fully read long names and descriptions (e.g. an Engineering Request name or a Task title) according to my preference, without the text being cut off.

> Extends **"COEMS- Enable listing page column wider"** (drag-and-expand column resizing on listing pages) to the Engineering module. Originally raised for the Group Worklog table (**COEMS-23586**); the scope now also covers the **Engineering listing** and **Engineering Task listing** pages. Where this story differs from the generic listing-page story (e.g. the Group Worklog's per-widget saving and reset on grouping change), this story applies.

---

#### **acceptance criteria:**

1. **Where it applies**

   Column resizing must be available in the following Engineering tables:

   * **Group Worklog table** — every Group Worklog widget, whether opened from the **Group WorkLogs** sidebar item or from the **Group Worklog Dashboard** tab on the Engineering Dashboard page (the same underlying feature).
   * **Engineering listing page** — opened from the **Engineering** sidebar item.
   * **Engineering Task listing page** — the task table opened from the **Engineering Task** sidebar item (the Kanban board is not a table and is not affected).

2. **Which columns are resizable**

   | **Table** | **Resizable columns** | **Not resizable** |
   | --- | --- | --- |
   | Group Worklog | Only the columns generated by the widget's descriptive selections — **Categorised By** (e.g. "Eng Request" and "Name / Description" when Categorised By is Engineering), **Group By** (e.g. "Engineering Type"), **Secondary Grouping** (e.g. "Task") and **Tertiary Grouping** (e.g. "Subtask") — whichever field is chosen | Estimation, Cumulative logs, Total and the period columns (e.g. Tue 01 Sep, Wed 02 Sep), which keep their fixed width |
   | Engineering listing | Every data column currently shown (e.g. Name, Eng Project Number, Description, Deadline, Loading Method … Final Performer) | The row-selection checkbox column |
   | Engineering Task listing | Every column of the task table (ID, Number, Name, Description, Status, Priority, Start Date, Due Date, Reporter, Assignee, Time Logged, Cumulative Time, WIP/Usage %, Is Flagged) | A row-selection checkbox column, if shown |

3. **Drag-and-expand icon**

   The header of each resizable column must include a **drag-and-expand icon** (at the column's edge) to indicate that the column can be resized.

4. **Resizing**

   * The user must be able to widen or narrow a resizable column by dragging its drag-and-expand icon, based on their viewing preference.
   * A column cannot be narrowed below a minimum width at which its header and values remain usable.
   * The user must be able to widen a column enough to fully view long values, such as an Engineering Request name or a Task title that is cut off at the default width.
   * Resizing one column must not change the width of any other column — the columns to its right shift along, and the table's horizontal scroll extends to fit.

5. **Applies to the whole column**

   The new width must apply to the column header and to every cell of that column in the table — including cells that span several rows and the summary row at the bottom (the **Grand Total** row in the Group Worklog, the **Sum Row** in the Engineering listing, when shown).

6. **Saved automatically per user**

   * The width of a resized column must be **saved automatically** for the user as soon as they finish resizing — no Update, "Save Filter" or other save action is needed.
   * When the same user closes and later reopens the table (including after reloading the page or logging in again), the previously saved widths must be restored and displayed.
   * Widths are saved **per user** — another user's widths are not affected.
   * **Group Worklog:** widths are also saved **per widget** — resizing a column in one Group Worklog widget does not change the widths in another.
   * **Engineering listing and Engineering Task listing:** widths are saved **per page**, and belong to the page rather than to a tab or view — the same widths apply across the status tabs (All, New Inquires, Under Discussion, …) and the List / Trash toggle on the Engineering listing, and across the My Task / All Tasks / List / Archived view modes on the Engineering Task listing.

7. **Works with Show/Hide & Reorder Columns**

   Where the user can show, hide or reorder columns (e.g. the Engineering listing — see "Engineering - Show/Hide & Reorder Columns"), a column's width belongs to the column itself:

   * Hiding a column and showing it again must restore it with the width the user had set.
   * Reordering a column moves it together with its width.

8. **Group Worklog only — reset when the grouping changes**

   When the user changes **Categorised By**, **Group By**, **Secondary Grouping** or **Tertiary Grouping** and the table is refreshed with the new selection, all resizable columns must return to their **default width**, and the widths previously saved for that widget must be cleared. The user can then resize again from the defaults (AC 6 applies to the new widths).

9. **Widths kept otherwise**

   * **Group Worklog:** changing the Date Range, Offices, Groups, Users, Module, Related Item, Period Grouping or Time Factor, clicking Update, or showing/hiding the Estimation and Cumulative logs columns must **not** change the saved column widths.
   * **Engineering listing and Engineering Task listing:** searching, adding or changing filters, switching status tab or view mode, sorting, paging (Page X of Y, Items per page), the List / Trash toggle, and refreshing the data must **not** change the saved column widths.

10. **Default width**

    A resizable column the user has not resized shows its current default width (as it does today).

---

#### **Scope:**

| **Area** | **Change** |
| --- | --- |
| Group Worklog widget → table | Drag-and-expand icon on the Categorised By, Group By, Secondary Grouping and Tertiary Grouping columns |
| Engineering listing page → table | Drag-and-expand icon on every data column; works with Show/Hide & Reorder |
| Engineering Task listing page → task table | Drag-and-expand icon on every column |
| Table body / summary row | New width applied to every cell of the resized column, including the Grand Total / Sum Row |
| User preferences | Column widths saved automatically per user (per widget for Group Worklog, per page for the listings); Group Worklog widths cleared when the grouping changes |

---

#### **Out of Scope:**

* Resizing the Estimation, Cumulative logs, Total or period columns of the Group Worklog.
* Any control to reset column widths to default. In the Group Worklog, "Reset Form" is not specified to reset widths — it affects them only if it changes the grouping selections (AC 8 then applies).
* Applying the widths to the Excel export.
* The Engineering Task Kanban board.
* Other Engineering tables — the Loading Method, Engineering Type and Document Search list pages, and tables inside an Engineering Project (Tasks tab, Quotations, Files, etc.).
* Column resizing in other modules — covered by "COEMS- Enable listing page column wider".
* Reordering columns (see "Engineering - Show/Hide & Reorder Columns").
